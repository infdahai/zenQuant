# Rust 模块边界

当前保留两个 crate、同机进程内调用，不建立服务、通用 Repository trait、事件总线或空接口。四个逻辑边界按职责划分，不要求四个 crate。人工与算法是输入来源，不是两套交易路径。

| 边界 | 现有文件（相对于 rust） | 允许依赖与职责 |
|---|---|---|
| 合约与计量 | options-core/src/{contracts,decimal,measurement,error,codec,canonical}.rs | 共同基础：产品/币种/单位/时间字段、精确数、规格/数量/tick 规则、严格解码与规范 hash；不依赖分析或交易状态 |
| 期权分析 | options-core/src/{inputs,costs,expressions,constraints,quote_diagnostics,terminal_diagnostics}.rs | 依赖基础及本组；纯报价/条件终值诊断，不读账户、不预留、不执行 |
| 交易内核 | options-core/src/{intents,reservations}.rs | 依赖基础及本组；意图语义、资金注册、幂等业务结果、余额准入、ACTIVE 状态与守恒；不依赖诊断、不做 I/O |
| 外部适配 | options-workbench/src/{main,report,io,publication,intent_store,reservation_store,snapshot_file}.rs 与 src/bin | 调用 core；负责文件边界、实际时钟、锁、提交与输出。core 不反向引用 workbench |

`contracts.rs` 保留旧 v1 View、假设钱包及报告类型，避免大范围搬迁；这些类型不代表真实资金权威。`StatusResult` 也是已有共享结果词汇，计量规则保留其既有失败语义，交易准入映射为自身拒绝结果。`costs`、`inputs` 的少量内部再导出只兼容现有分析调用者，规则实现只存在于 measurement。禁止再从交易内核导入这两个分析模块。

`fixtures.rs` 是明确的数学样例构造器，构造分析和交易输入，是唯一显式跨组样例例外；旧 v1 内置 fixture 入口仍使用它。它不承载账户决策或状态转移。不要通过 fixture 增加生产业务依赖。报价和终值各保留严格独立请求，只共享实际计算；不增加统一的多模式分析大函数。

## 两种存储的权威边界

意图归档只保存输入：`RECORDED_UNASSESSED` 永远不代表批准。core 的 `compare_identity` 决定同 ID 同语义/冲突；归档提交序号、首次原始字节 hash、文件容量及原回执留在 `intent_store`。它不得演化出资金、订单或成交状态。

`reservations::Authority` 是当前唯一资金业务状态，数据字段私有。新状态只能由纯 `fund` / `reserve` 转移或完整校验后的反序列化取得；状态内保存全部资金初值、原请求、首次预留结果及 ACTIVE 记录，可用金额派生。换持久实现仍调用这些转移，不在新适配器复制余额准入逻辑。

```text
外部严格读取 → 独占锁 → 读取并验证整个 Authority → 读取真实时钟
             → core 纯转移 → 持久化同一完整状态 → 确认回执
```

纯转移返回待提交状态，不是持久化成功或交易授权。资金与可供幂等重试的结果在同一快照提交，不能先单独扣余额再写请求。反序列化重验历史准入、唯一 ID、序号、成本和守恒；纯结果与持久化重放的业务结果必须一致。当前 v1 的预留金额必须能被其精确 Dec 解码器读回，超出精度直接拒绝，不舍入。

权威定位暂为构建仓库固定目录，linked worktrees 共享普通仓库根；任意当前工作目录不产生新资金池。这只是单仓库模拟实例边界，独立 clone/主机不提供真实账户全局协调。未来适配真实账户必须先定义可验证账户身份、部署权威和恢复边界。

未来 OMS、成交与账本仍属于交易内核逻辑，同资金域维持唯一权威；成交去重、数量与现金守恒、重启可重放以及状态推进与资金占用一致是必要不变量。外部交易所读写属于适配层。本轮没有这些状态、接口或实现，也没有自动过期/取消释放。

## 版本、兼容与退役

| 版本域 | 规则及退役条件 |
|---|---|
| 输入/输出 schema | 原 v1 View 必填、未知字段拒绝继续冻结；新增独立能力使用独立名称。不通过放宽旧 schema、填造 View 或把诊断报告当意图兼容。退役须识别消费者、给出显式迁移、验证保留语义并获准移除；本轮不退役任何契约 |
| 模型版本 | 终值模型仅声明其支持产品和到期时点；数学变化独立升级模型版本，保留旧模型复现证据。模型 VALID 不代表账户或执行有效 |
| 持久化 schema | 与请求及模型分别演进。变更前必须验证初值、ACTIVE 金额、请求身份、历史结果、序号/时点及重试语义守恒；迁移只能整体切换权威，不能双写假装事务。需备份、失败/重启及回退规则后方可退役旧读法。本轮无迁移实现 |

UNKNOWN/UNVERIFIED、证据身份、时点有效性、原子报告发布及封存限制继续保持。源 hash 是身份/完整性字段，不自动认证真实账户或交易所费率。当前费用上界只是明确标注的模拟声明。

## 机械检查的覆盖范围

`cargo test -p options-core --test architecture --locked` 是新增的 Rust 原生架构检查；既有 `public_boundary` 是输入行为回归，二者不同。

检查通过一个小型源码词法扫描器核对 core 的显式 `crate::` 边，支持当前平铺模块的普通/分组 use、别名和全限定路径；跳过注释、字符串、raw string 和常用字符字面量。模块必须登记归属；新增子目录需显式扩展检查。它还限制直接 std/core/alloc 模块使用，拒绝未审查宏、extern crate 和相对模块路径绕行，并用 Cargo 的原生 metadata 确认两个 workspace crate、core 无 build script 且依赖仍是已审查的六个纯计算/序列化库。测试自身的文件和 Cargo 访问不属于生产 core。

这是**直接源码依赖检查**，不是 rustc 名称解析器、宏展开器或全程序无副作用证明；不分析过程宏展开、传递依赖内部行为、trait/回调副作用或业务规则是否被复制。样例构造有上述显式例外。遇到新增 Rust 语法/能力应审查并扩展检查，而不是把失败变成任意白名单。拒绝案例测试覆盖组导入、别名、I/O/时钟路径、分析到交易及基础到交易的错误边。

业务证明主要来自纯内核不变量测试；适配测试专门验证锁、短写、持久性不确定、SIGKILL 恢复和回执兼容。旧字节 golden 是旧契约的兼容证据，不要求未来所有存储永远使用同一 JSON 布局。

## 克制与新增准入

- 保留两个 crate、同步调用、直接快照基线。没有缓存、并发余额计算或提前造出的可替换框架。
- 本轮全量快照实测随容量增长明显，不满足高吞吐结论；先明确实际负载和接受阈值，再考虑替代，不立即引入数据库。
- 新模块须说明实际问题、现有职责为何无法清晰承载、输入/输出、允许依赖、唯一状态所有者、可验收不变量和移除/替换条件；仅有未来设想不构成准入。
- 禁止按人工/指标来源复制风控执行，按产品另建资金权威，适配层加入第二份决策规则，跨文件双写金融状态，以及通用 DSL、微服务或无调用者接口。
