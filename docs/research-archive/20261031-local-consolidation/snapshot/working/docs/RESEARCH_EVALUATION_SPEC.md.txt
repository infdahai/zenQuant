# ZenQuant 综合评价体系

证据日期：2026-10-02；审阅完成：2026-10-03。版本：`research-evaluation.design.v1`。
状态：**综合评价规范；2026-10-03 已分层实现基础评价、风险诊断、regime 归因及多次实验裁决。**
完整能力与实测结果见 [研究框架操作指南](RESEARCH_FRAMEWORK_GUIDE.md)；本规范不是准入结果。
适用 BTC 首轮研究，架构与实施顺序见
[工程与研究框架](superpowers/specs/2026-10-02-research-engineering-framework-design.md)。

## 1. 评价原则与结论结构

评价必须同时回答：数据和账本是否可信，收益来自什么，承担多少风险，成本和扰动后是否保留，
是否只是选参偶然，以及在真实运行中能否持续复核。

使用 **硬门槛 → 多目标取舍 → 独立证据成熟度**，不使用把十几个维度加权成一个总分的准入方式。
Sharpe、收益、回撤、Calmar 高度相关，不应重复投票；无亏损或零波动不能自动得到完美分数。

每项记录：`metric_id / definition_version / value / unit / sampling / window / sample_size /
status / reason / confidence_interval / policy_threshold / source_hash`。

| 结果状态 | 含义 | 必需项对晋级的影响 |
| --- | --- | --- |
| PASS | 证据完整且达到冻结条件 | 仅该项通过 |
| FAIL | 已有效计算且不满足条件 | 阻断 |
| NOT_EVALUABLE | 数据、样本或比较条件不足 | 阻断，保留缺口原因 |
| NOT_RUN | 尚未执行 | 阻断 |
| INVALID | hash 不一致、泄漏、会计失真或协议被改变 | 本次相关研究结论失效 |
| STALE | 对旧代码/配置有效，对当前候选不再适用 | 重新评估后才可使用 |
| NOT_APPLICABLE | 冻结协议预先声明不适用 | 保留理由；不能事后用来跳过失败 |

单个未完成项不使其他已经验证的观测消失；总体结果必须同时列出通过、失败和缺证项。
展示“研究有希望”与“具备运行资格”使用不同字段。

## 2. 基础口径

### 2.1 资金、时间、成交与收益

- 账户计价 USDT；BTC/其他计价另列。首轮固定初始资金 100,000 USDT、无外部资金流。
  未来存在入出金时按资金流前后估值分段计算 TWR，不能直接用利润/累计充值替代。
- 统一 UTC，窗口 `[start, end)`；事件频率、4h 估值、日收益分别标注。
  日收益取 UTC 日界的已知估值；不可用未来报价补日界。数据缺口携带质量状态，不填成零收益。
- 用实际成交更新仓位。线性永续账户核对：
  `NAV = initial_cash + external_flows + realized_price_pnl + unrealized_pnl - fees + funding_pnl`。
  `funding_pnl` 收入为正；同时提供支付为正的 `funding_cost` 时必须标明符号。
- 模拟滑点已体现在成交价格中，不再次从 NAV 扣除。费用压力必须在回放时进入账本和后续风控，
  事后减去估计费用只能叫近似归因，不能当真实压力验收。
- 候选与基准同资金、可用数据、交易日历、决策/执行时间、手续费、资金费、滑点和杠杆约束。
  confirmed close 决策不得声称能无延迟按刚刚形成的 close 成交；默认研究比较在之后可用报价执行。
- 4h 最大回撤仅表示 4h 采样回撤。需要 5m/成交事件级 mark 才能评价更细风险；OHLC 极值只能作
  保守边界，不能编造成已经观察的盘中 NAV 路径。粗采样结果不能给更细风险门槛 PASS。
- 任何 NAV≤0 触发 `ruin` 硬 FAIL，终止策略的正常收益率评价；保留全部账户损失和事件轨迹。
  从最后正 NAV 到首次非正 NAV 的损失保留，不继续对负分母计算普通收益率；后续 Sharpe/Sortino
  为 NOT_EVALUABLE。破产前统计只能带终止标记作诊断，不能删去失败段后进入候选排名。

### 2.2 指标定义

下表为新评价版本；当前 `BacktestMetrics` 原字段保留，并明确 old/new definition。

| 指标 | 计算与边界 |
| --- | --- |
| 净总收益 | 无资金流时 `NAV_end / NAV_start - 1`，未平仓仓位盯市纳入；另列已实现与未实现贡献 |
| CAGR | 正净值时 `(NAV_end/NAV_start)^(365/elapsed_days)-1`；不足一年只作外推描述；非正净值标破产，不丢弃该段 |
| 日 Sharpe | `mean(r_daily-rf_daily)/sample_std(r_daily-rf_daily)*sqrt(365)`；首轮 `rf=0`，明确是零现金收益基准；零波动为不可评价 |
| 日 Sortino | `mean(r_daily-MAR_daily) / sqrt(mean(min(r_daily-MAR_daily,0)^2)) * sqrt(365)`；下行平方均值包含全样本；首轮 MAR_daily=0；非零 MAR 的频率及换算提前冻结；无下行样本不可评价 |
| 最大回撤 | `max(1-NAV_t / running_peak_t)`，注明采样；负净值不截断为零，不把超过 100% 的损失隐藏 |
| 回撤时间 | 最长水下时间、峰到谷时间、谷到恢复时间；窗口末未恢复标 censored，不能写恢复零天 |
| 尾部损失 | 日损失序列的 worst day、worst week、95% 分位和 Expected Shortfall；不足尾部观测数时不给精确风险结论 |
| episode PF | 平仓 episode 的正净 PnL 总额 / 负净 PnL 绝对总额；含分配的 fee/funding；无亏损用 `NO_LOSS_EPISODES`，不填无穷大或零 |
| 胜率/盈亏比 | 以闭合 episode 为单位；fill 数不作独立样本数。未平仓另报持有期、MFE/MAE 和利润集中度 |
| 换手 | `sum(abs(fill_qty*fill_price))/initial_equity` 为初始本金周转倍数；另列按成交前 NAV 归一化周转率和 USDT/day；不混用 |
| 费用负担 | fees/initial_equity、funding_cost/initial_equity、slippage attribution；fees/gross_pnl 仅 gross>0 时定义，非正时不可评价 |
| 敞口效率 | 时间加权绝对敞口、持仓时间占比、risk budget 使用率及对应净收益；空仓时不除零，不能把低敞口本身当 alpha |
| 盈利集中 | 最大 episode、最佳月份、最长趋势对总收益的贡献；净收益接近零时改列金额和移除后结果，不使用爆炸比例 |
| 执行质量 | fill ratio、成交延迟、滑点分布、撤单/拒单/部分成交、target tracking error、maker 实际比例；只有订单簿或成交证据才支持容量判断 |

收益自相关会影响 Sharpe 推断，`sqrt(365)` 仅作为统一描述口径；置信区间保留时间相关性，
不把每根 bar 当独立样本。参见 [Lo 的原始研究](https://alo.mit.edu/publications/page/18/)。

## 3. 综合评价矩阵

`E` 为工程硬门槛，`R` 为研究筛选，`O` 为运行资格。筛选数值取自运行前冻结的 policy。
未配置必需阈值不得用默认零值放行。

| 维度 | 评价内容与证据 | 判定及动作 |
| --- | --- | --- |
| E0 来源与身份 | 代码/数据/profile/model/hash、版本、候选对应、结果完整性 | 不匹配为 INVALID；旧证据为 STALE；停止排名 |
| E1 数据与时间因果 | 来源可信度、coverage、缺失/延迟、as-of、修订、warmup、确认收盘、去重 | 任何未来泄漏为 INVALID；必需数据不足 NOT_EVALUABLE；不以插值伪造来源 |
| E2 账本与库存 | 每次 fill/funding/mark 的独立现金、库存、NAV 核对，部分成交/反转/费用分配 | 无来源资金、重复入账、费用漏扣为 FAIL；先修会计再谈收益 |
| E3 确定性与 parity | 同事件同 config 的目标、风险、成交、账户 trace；restart/replay | 未解释差异 FAIL；网络/墙钟与随机数不得进入策略纯计算 |
| E4 执行与风险权限 | 下一可用报价、部分成交、最小量/精度、延迟、仓位上限、紧急减仓、执行纯度 | 越权加仓、意外反转、目标超调、风控无法覆盖均 FAIL；无法复现实盘假设则限制结论 |
| R0 绝对收益质量 | 净收益、CAGR、Sharpe/Sortino、PF、盈亏比、已实现/未实现贡献 | 每个窗口及区间报告；不只展示盈利窗口；净值正不等于超额 |
| R1 增量价值 | 同风险预算基准、配对超额收益、收益差区间、bull/bear capture、敞口差 | 执行条件不同则 NOT_EVALUABLE；简单基准足够好时不得仅凭复杂度选新策略 |
| R2 资本风险 | MDD、最长水下期、尾部损失、波动、杠杆/保证金、强平、连续亏损 | 超冻结限额 FAIL；无强平模型则相应项 NOT_EVALUABLE；报告采样频率 |
| R3 跨阶段行为 | 按当时可得 regime 标签、年度/月份/滚动窗、牛熊震荡、方向与状态切换 | 报最差阶段及覆盖数；某阶段缺样本不宣称全市场稳健；事后标签只作诊断 |
| R4 成本与容量 | 换手、fee/funding/slippage、额外 0/5/15bp、maker/taker/partial-fill 情景、资金规模曲线 | 成本压力全量重跑；缺盘口/参与率证据则容量 NOT_EVALUABLE；不靠假设 maker 免费成交 |
| R5 泛化与选择偏差 | 时间分割、内层验证/外层评价、全部 trials、研究谱系、重试、DSR/PBO 适用性 | 验证/测试反馈污染必须披露；信息不足不报校正置信；测试不参与寻优 |
| R6 稳健性与敏感性 | 五 seed 扰动、参数邻域、起止时间、价格/数据缺失/延迟、成本压力 | 固定 seed 至少 4/5 满足冻结经济门槛；任何工程安全失败不能被 4/5 豁免 |
| R7 复杂度与可解释性 | 参数维度、因子/动作归因、消融、故障面、训练/推理成本和可复现预算 | 统计与经济差异不能区分时优先较简单方案；不按因子数或模型规模加分 |
| O0 运行可靠性 | 数据 freshness、审计写入、完整 bar 处理、重连、恢复、reconcile、版本漂移、kill 演练 | 丢审计、重复资金事件、版本混用、风险失效为硬阻断；时长达标不等于盈利证据 |
| O1 前瞻证据 | 冻结后真实新数据、实际/模拟执行区分、paper 与 replay 差异、滑点/成本偏差 | 绑定候选版本和冻结时间；缺足够周期/交易/行情覆盖则继续观察；真仓仍走操作人决策 |

这 15 个维度不产生 15 个可互相抵消的分数。必须项按阶段生效：历史研究需要 E0–E4，
进入冻结候选需要预声明的 R 项；运行资格还需 O 项和交付规格。诊断模式可运行失败样本，
但报告显式 `diagnostic_only`，禁止进入候选排序或自动晋级。

## 4. 初版研究 policy 建议值

下列是**新研究线的设计建议，尚未激活**；不是改写 Quant V2 的历史 20% 门槛或当前 production 配置。
未列为硬门槛的指标仍完整报告；任何事后阈值调整要生成新 policy 版本和研究后代。

| 条件 | 建议 v1 规则 |
| --- | --- |
| 账本误差 | 首轮 100,000 USDT 研究资金下逐事件现金/NAV 绝对残差 ≤ 0.000001 USDT；库存按 venue 数量精度核对；容差事前固定 |
| 信息泄漏/重复入账/越权风险 | 0 次；任一 seed 发生都阻断，不参与投票 |
| 回撤目标 | 每个声明的开发评价窗口 MDD ≤ 15%，注明估值采样；仅研究筛选目标，不保证未来回撤 |
| 成本复跑 | 完整执行额外 0/5/15bp 每次成交不利成本；每档按逐笔名义额入账，保留风险路径变化 |
| 成本生存条件 | 完整开发区间连续回放在基础与 +5bp 下净收益 > 0，不重复累计重叠窗口；逐窗口收益另列，不要求每个窗口盈利。+15bp 默认压力展示；若要晋级，必须事先冻结该档净收益或亏损上限，缺值阻断晋级。原 Quant V2 的 +15bp 正收益条件继续按原 scope 生效 |
| 扰动 | 每候选固定五 seed，每个完成相同的必需窗口×成本矩阵；同一组至少四个 seed 在基础和 +5bp 下均满足完整开发区间净收益 > 0、每个必需窗口 MDD ≤ 15%；其余 seed 完整报告；所有 seed 的工程安全门槛都必须通过 |
| 基准增量 | 主基准是冻结的 BTC 波动目标/现金策略；同资金和执行条件；配对日均净超额的 95% 时间块 bootstrap 区间下界 > 0 才标“历史增量证据成立” |
| 统计样本 | 初版至少 180 个有效日收益、30 个闭合 episode 用于 PF 稳健判断；95% ES 至少 20 个尾部观测；不足就把对应结论标 NOT_EVALUABLE，不通过增加交易奖励凑样本 |
| 参数邻域 | 选中候选每维相邻一档单独扰动，其他维不变；可行邻居至少 80% 通过基础经济门槛，并报告全部收益差；边界没有双侧邻域时注明，不伪造对称验证 |
| 工程检查 | 对应改动所需检查及 merge 前完整 `zenquant-check` 通过；不得把旧 golden 更新为“看起来好”的新结果 |

180 天、30 episode、20 尾部观测与 80% 邻域是事前选定的首轮研究假设，不是论文保证。
极低频策略可能长期不足 episode；可以保持研究状态，不能给“样本充分”的结论。
risk budget/杠杆上限沿用实验事先冻结的值，基准与候选一致；缺值拒绝启动，不从测试实现波动反求。
五 seed 的缺跑、超时、无效矩阵为证据不完整，须补全后才能裁决；不缩分母，也不在各个成本档
挑不同的四个 seed 拼成通过。完整开发连续回放和子窗口的起止/持仓 carry 或 reset 规则分别冻结。

## 5. 基准、分区与统计协议

### 5.1 对照组

固定四组：现金、BTC 1x 持有、BTC 波动目标/现金、简单趋势 + 相同波动目标。
1x 只作市场参照，主要增量检验使用同风险预算的冻结主基准；禁止看结果后改“最好打败”的基准。
按相同持仓约束评估多空候选；long/short 的额外自由度与借贷/资金费完整披露。
多资产实验以后扩展，必须同时报告同名义敞口和同事前风险预算，不能把提高风险当分散收益。

### 5.2 时间隔离

- 训练只用 train；可在 train 内做多段顺序验证和有限 early stopping。dev 仅用于固定候选集的
  选择/诊断，不得把 dev 分数送回宣称 train-only 的 sampler。
- 外层时间窗、purge/embargo、label horizon、warmup、归一化训练区间在运行前固定。
  purge 处理跨边界标签；历史特征 warmup 可以读取过去，但不读取未来或计入评价 PnL。
- 不同候选使用同一时间窗；先保存冻结候选清单，再打开选择窗口。任何 dev 反馈再做的新候选
  都记录为后续开发迭代，不能当一次未接触验证集的实验。
- 当前 2026 历史已观察，评价角色为 observed historical；未来独立区间从候选及规则冻结后开始。
  旧 `test` 标签本身不能证明独立性。新测试数据首次打开和每次读取均记录。
- 滚动报告同时提供逐窗口分布和无重叠拼接的资产曲线；有重叠窗口不得重复累计收益。

### 5.3 不确定性与多次搜索

首轮配对日收益差使用固定 seed 的时间块 bootstrap。块长在训练阶段按持有期/自相关诊断确定，
并冻结短/基准/长三个块长作为敏感性；建议 2,000 次重采样，披露区间稳定性。
只有事先规定的结论规则成立才显示“增量证据成立”；跨块长结论不同标敏感，不能挑最好一个。
该区间不能消除反复选策略的偏差，dev 结论仍是开发证据。

所有尝试（含失败、超时、剪枝、人工改参、AI 改因子和 RL seed）记录在研究谱系中。
[Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf) 用于检查多次筛选、
非正态及有限样本的影响，所需 trial 与收益分布信息不足则不可评价。
[PBO](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) 需要共同样本上的候选收益矩阵；
只存冠军或各候选在不同窗口的标量成绩无法计算可信结果。它是额外选择偏差诊断，不能替代
按时间的前瞻验证。两项不设可被优化器反复追逐的“神奇合格概率”。

## 6. 综合决策与搜索目标

### 必需的消融与精简规则（2026-10-03 用户追加）

每项新增信号、过滤器、策略状态、适应规则或模型都建立组件清单，并事先冻结“完整版本、
逐项移除版本、简单基准”的实验矩阵。先做单项消融，只有发现交互作用才增加必要的组合；
不无上限地穷举组合。统一窗口、warmup、初始资金、成本、风险预算和执行条件，删除组件
不能同时重新调参来掩盖影响；需要重新调参时另立后代实验并计入总搜索次数。

判断至少覆盖配对净收益差及区间、回撤与尾损、换手与费用、阶段表现、扰动与参数敏感性、
计算成本和故障面。结论使用 `KEEP / REMOVE_CANDIDATE / INCONCLUSIVE`，附证据与理由。
无法证明稳定增量时优先简单方案；样本不足不能写“已证明无效”。删除提议仍需对应回归验证。
风控、账户真实性、PIT、费用入账和审计是不可消融的不变量；研究执行始终保留它们。
R7 完整性要求组件清单、必需消融完成度与取舍记录；没有做消融不得宣称复杂度已经合理。

### 搜索与筛选规则

1. 先排除 INVALID、STALE、硬 gate FAIL 和必需证据不足的候选；不把它们按低分混入好候选。
2. 通过后保留三个主要比较轴：跨共同窗口的净超额收益、最差回撤、归一化换手/成本。
   窗口收益不能简单平均不同长度的累计收益；使用共同日频定义及逐窗分布。
3. 保留 Pareto 集：不存在另一个候选在三轴均不差且至少一轴更好。再按稳定性、区间重叠、
   参数复杂度和实现成本判断取舍。统计上无法区分时保留简单基准。
4. 不把 15 个维度全部变成优化目标；维度过多会让大部分候选互不支配。
   [Optuna 官方说明](https://optuna.readthedocs.io/en/stable/tutorial/20_recipes/002_multi_objective.html)
   也建议将适合的要求作为约束。接入时按本仓库已安装版本核实 API，不顺带升级依赖。
5. 搜索目标可以是冻结的代理指标，但最终评价独立且不可被 sampler 改写。
   Random/TPE 比较计入全部评估次数、bar 数、CPU/墙钟、失败和缓存；RL 还计入梯度更新数、
   environment steps、调超参和多 seed 成本，不能用 episode 数冒充同等计算预算。
6. 预算耗尽、同类失败反复出现或无可行区域即按冻结 stop rule 结束；不自动加预算直到出现冠军。

## 7. 统一交付报告

每个候选输出一张卡和可复算底账，内容顺序固定：

1. 身份、数据时间、实际运行路径、证据成熟度、总体 blocker。
2. 工程 gates 与缺证项；不能藏在收益图之后。
3. 同条件基准表：收益、DD/水下时长、Sharpe/Sortino、PF/样本、换手、费用、敞口。
4. 净值/水下曲线，按年和当时 regime 分解，已实现/未实现与少数交易集中度。
5. 成本压力、五 seed 分布、参数邻域、最差窗口和反例。
6. 统计区间、累计搜索次数、数据被查看历史、计算预算和失败记录。
7. 前瞻观察、运行健康、parity 与下一项所需证据；状态由同一 evaluator/resolver 生成。

历史样本中的声明不得超过证据：本轮当前插件 dev 净收益 -13.78%、4h DD 30.55%，足以拒绝
该窗口经济筛选；它不能证明所有 BTC 策略无效。2026 历史盈利不能覆盖 dev 失败，也不能替代
未来观察。已有局部账户 parity 不能显示“全链路 live parity 已通过”。

## 8. 实施验证清单

- 用独立小账本验证手续费、正负资金费、未平仓盯市、部分成交、反转、入出金与负净值。
- 用手算日收益验证采样/Sharpe/Sortino/回撤持续时间；验证零波动、无亏损、缺日期和不足样本。
- 校验所有 nullable 值保留状态和单位；旧的 0 不直接迁移成新指标的 PASS。
- 改测试集和 dev 内容不影响 train-only 搜索序列；同窗口同 seed 可复现，异步调度次序需可重放。
- hash 或实际配置变化后旧 evidence 不可复用；作业 interrupted 不得输出 completed 验收。
- 通过构造候选检验硬 gate 不被高收益抵消、Pareto 方向正确、同分的稳定 tie-break。
- 启动/重连/恢复、重复 bar/fill/funding、stale 数据和 kill 路径验证通过后，才做运行资格判断。

基础评价器、证据导入与报告、风险诊断、因果 regime 标签、配对 bootstrap、seed 矩阵、
Pareto 与状态投影已有独立实现和契约测试。尚不能据此声称全事件 live parity、交易所容量、
保证金/强平、DSR/PBO 或未来观察已验证。完整 seed/成本/邻域实验需按候选另行执行，
不能把函数测试通过当成策略通过。当前历史阻断保留；不会因增加评价维度自动成为可部署策略。
