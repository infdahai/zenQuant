# Live Validation Handoff Spec

> Architecture scope: this file remains the current tester/operator contract for
> the existing production baseline. Quant System v2 is implemented only as an
> explicit research path and has not been promoted. See
> [`QUANT_V2_ACCEPTANCE_HANDOFF.md`](QUANT_V2_ACCEPTANCE_HANDOFF.md) for its
> current blocked verdict and [`ARCHITECTURE.md`](ARCHITECTURE.md) for boundaries.

本文件是当前版本唯一的 tester / operator 交付规格。

目标只有一个：

- 开发负责人完成当前功能、验证与运行闭环
- 测试负责人按本文件执行并记录结果
- `framework_optimization.json.final_verdict` 满足历史准入条件只是必要条件；
  新 donor 还必须通过单独冻结的 Quant V2 acceptance，才具备进入 `paper-live` 的资格

本文件是测试负责人与 `paper-live` 操作人的唯一入口。研究型文档仅作内部参考，不作为交付依据。

严格数据切分前置条件：

- `train = 2020-01-01 ~ 2023-12-31`
- `dev = 2024-01-01 ~ 2025-12-31`
- `test = 2026-01-01 ~ latest`
- `paper-live` 只能在冻结 `test` 历史验收通过后启动

切分纪律说明见 [`DATASET_SPLIT_POLICY.md`](/Users/disaster/workspace/code/zenQuant/docs/DATASET_SPLIT_POLICY.md)。

## 5. Promote / Stop 规则

### 5.1 测试通过后何时允许直接启动 `paper-live`

同时满足以下条件，才可以把候选表述为 `eligible_for_paper_live` 并直接启动：

- 第 2 节所有关键测试通过
- 第 2 节脚本级验证通过
- live runtime 与 live validation 入口可用
- 本文档所列启动命令、导出命令和停机规则均已可执行
- `results/framework_optimization/framework_optimization.json` 中：
  - `final_verdict.test_evaluated = true`
  - `final_verdict.promote_to_paper_live_candidate = true`
  - `final_verdict.blocked_by = null`

### 5.2 运行中必须停止的情况

出现以下情况必须停止 `paper-live` 并回到研发/排障：

- `/healthz` 非 `ok`
- 市场数据断流或持续 stale
- 审计数据库掉线或持续无 writes
- `database_dropped_writes > 0`
- 连续缺失 4H state / target / sizing / playbook
- 关键质量标志异常持续不恢复

### 5.3 何时才可声称 paper trading 完成

只有同时满足以下条件：

- 连续稳定运行满 `2 weeks`
- 无崩溃
- bar close、决策、审计均持续正常
- 至少完成一次正式 `paper-live` 导出
- 至少完成一次正式 `paper-live` review

在满足这些条件前，只能表述为：

- `paper-live started`
- `paper trading in progress`

不能表述为：

- `paper trading complete`
- `live incremental validation complete`

### 5.4 真仓 promote 条件

本轮不进入真仓，但后续讨论真仓前至少要求：

- paper-live 完整通过
- parity / execution / risk review 无重大异常
- live review 证明系统行为与历史验证框架一致

## 6. 为什么当前版本值得进入 `paper-live`

不是因为当前已经证明收益碾压 `paulwei_baseline`，而是因为：

- 状态、风险、执行链路更可解释
- replay / backtest / live 一致性约束更完整
- 审计与导出链路已具备
- 已知历史弱窗口已有定向修复
- 防过拟合门槛已经内建到测试和验证体系中

当前防过拟合依赖的不是单一回测，而是：

- walk-forward OOS
- historical adversarial
- point-in-time correctness
- replay/live parity
- golden + invariants + parity regression
- 缺失数据 fail-closed

因此本轮交付的含义是：

- 系统已达到值得做 `paper-live` authoritative validation 的工程成熟度
- 不是说所有研究问题都已回答完毕
