# Supplied Binance kline ingestion

`zenquant history-import` converts a local, headerless Binance USD-M futures kline CSV into a `dataset-v1` JSON document accepted by the Go workbench. It performs no downloads and does not invoke Python. Supply the source identity and an explicit observation cutoff:

```sh
go run ./cmd/zenquant history-import --input /path/to/klines.csv --symbol BTCUSDT --timeframe 4h --as-of 2024-02-01T00:00:00Z > /tmp/btc-dataset.json
go run ./cmd/zenquant workbench --store /tmp/zenquant-research import < /tmp/btc-dataset.json
```

The caller must establish that the file is actually BTCUSDT USD-M futures data; CSV rows do not carry a symbol. Supported timeframes are 5m, 1h, 4h and 1d. Input must be the 12-column millisecond Binance kline format in ascending order. The command rejects invalid fields, duplicate or unordered bars, misaligned intervals, and any bar closing after `--as-of`. Binance's inclusive millisecond close becomes the exclusive interval end in nanoseconds, matching the Python downloader. Gaps are retained and reported by the workbench; they are not filled. A close at the cutoff is accepted.

Input is limited to 4 MiB, 20,000 bars, and the workbench's 1 MiB JSON limit. Only regular input files are accepted; symlinks and special files are rejected. Output is written only after validation succeeds. Redirect to a new file: shell redirection itself can truncate an existing file before the command runs. The workbench identifies the instrument as BTC, while the supplied source symbol is BTCUSDT.

This is a supplied-CSV kline subset, not a replacement for the complete Python monthly sync. It does not download or read ZIP archives, write the Python Parquet layout, import funding or open interest, verify archive provenance, or establish when historical data actually arrived. The cutoff only prevents inclusion of bars that had not closed by the stated time; it does not prove point-in-time availability. Empty funding means unknown coverage, not zero funding. No live trading or strategy parity is implied.

The checked-in synthetic reference was generated by `python3 scripts/generate_history_ingest_fixture.py` using the Python downloader's kline normalization with a synthetic ZIP and storage stubs. Go tests compare its normalized rows and exercise CLI ingestion, workbench import, a submitted diagnostic replay and its result, and the close-time boundary without Python. This establishes parity only for those fixture rows.
