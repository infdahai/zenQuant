# Legacy Go strategy flow boundary

`research.StrategyFlow` is an in-memory, single-owner pre-risk strategy component. Feed ordered, confirmed 1d market states, 4h indicators followed by matching 4h market states, and incremental actual fills. `State` returns the selected playbook, exit and sizing decisions, strategy target, intent reason and confirmation status when applicable. Targets are intents, not exchange orders or risk approval. Fill events must be deduplicated, ordered and admitted by the caller; the flow has no fill IDs, persistence or concurrency control.

The supported slice is the Python `ARCStrategyEngine` legacy 4h execution path with default playbook, sizing and exit settings, fixed equity, default flat/add/reduction behavior, optional entry and flip confirmation, and 1d directional bias. Intent UUIDs follow Python's UUIDv5 inputs. Actual fills update position quantity and weighted entry price; exit decisions use the filled position rather than a previous intent. A new flow starts flat. The caller must replay the ordered events to restore it.

A 4h state requires an indicator with exactly the same cutoff. Duplicate or older indicators and states are rejected without advancing that state, and future 1d bias is ignored for a 4h decision. This intentionally strengthens the Python cache's handling of stale and out-of-order data; it is not claimed as parity for those inputs. Daily bias freshness and quality follow the Python strategy. Inputs are restricted to BTC symbols, positive prices, finite numbers and the exit primitive's documented domain.

The Python-generated synthetic fixture covers entry confirmation, a confirmed flip, fills including additions and reductions, an unsafe-quality exit, and the emitted playbook, sizing, exit, target, reason and confirmation status at each 4h state. Fill residual and cutoff rejection tests separately cover behavior outside that fixture. Run `go test ./internal/research -run TestStrategyFlow` to verify it; regenerate the fixture with `PYTHONPATH=. python internal/research/testdata/generate_strategy_flow.py` in an environment with the Python project dependencies.

Unsupported: plugin signals, filters, sizers and exits; adaptive weights; lower-timeframe 1h/5m promotion; non-default flat, add, reduction, leverage-hold and other optional strategy guards; equity update events; risk overlay and final-target reconciliation; architecture alpha and V2 `DecisionSnapshot` publication; exchange execution, timestamps and deduplication for fills; position-state and detailed confirmation event payloads. No Python parity is asserted for these paths or arbitrary invalid inputs. The evidence is not the content-addressed, risk-approved `DecisionSnapshot`: that contract requires a matching risk decision and final target. This component is research infrastructure and has not been validated for live use.
